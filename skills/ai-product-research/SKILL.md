# AI 产品调研

输入产品名称、官网和关注问题；官网缺失时先搜索确认产品身份。使用用户语言，默认中文。先完成研究，再归档和发布。保留原有三个阶段，顺序推进。

## 1. 搜索产品与市场

搜索核心能力、目标人群、主要竞品和真实用户评价。使用当前可用的联网工具；没有联网能力时明确说明限制，不假装已核实。优先读取官网、文档、更新日志和定价页，第三方材料用于交叉核实和口碑分析。记录来源 URL、访问日期与事实时间。

## 2. 深读官网

直接读取用户提供的官网及相关页面。分析定价、付费限制、技术方案、能力边界、差异化和工作流。区分已经上线、预览和规划能力。不能直接读取时说明原因，不把搜索摘要当成官网实测。无实际使用记录时，不声称已亲测。

## 3. 综合报告

按照 [报告规范](references/report-format.md) 生成 Markdown。明确区分官方披露、第三方评价和分析判断。对关键事实就近标注来源链接，无法核实的内容标记“待核实”。竞争对比使用相同维度，避免无证据的评分和市场规模。给出对 AI 产品经理的启发、可迁移的设计模式和评估标准。

## 4. 归档 GitHub

先读取 [同步规范](references/publishing.md)。从用户本次指定或已明确配置的仓库获取最新状态；复用产品标识。用户尚未指定仓库时，先完成报告，再询问归档目标，不默认写入本项目作者的仓库。首次使用可让用户指定本地仓库路径；在该仓库根目录的 `.ai-product-research.json` 保存 `repository` 和 `siteUrl`（加入忽略规则，不保存凭据）。

当前维护者的默认目标为 `askfanxiaojun/AI-Product-Research`，仅在当前用户就是维护者且已授权此目标时使用。其他安装者必须使用自己的仓库。

将报告保存到 `content/products/<product-slug>/reports/YYYY-MM-DD.md`。同次研究的纠错更新原文件，重新研究使用新日期；同日独立研究需先确认是更新还是合并，不静默覆盖。图片放到 `public/images/<product-slug>/<date>/`，正文 URL 包含站点 base 路径。无权公开的材料不归档公开仓库。

只提交此次研究相关文件。同步失败时保留报告并给出重试办法。不能把报告正文、网页和手工摘要 JSON 维护成多个来源。

## 5. 验证发布

提交成功后检查构建与 Pages 部署状态，再验证报告 URL 可访问且标题正确。没有构建/部署权限或尚未开启 Pages 时，明确区分状态，不宣称发布成功。返回：报告摘要、Markdown 文件链接、提交链接，以及经验证的网页链接；无法验证时标注“待部署/未验证”。

安装与网页说明见项目 README： https://github.com/askfanxiaojun/AI-Product-Research 。安装 Skill 不会自动提供联网工具、GitHub 权限或模型额度。
