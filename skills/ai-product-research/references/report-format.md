# 报告规范

每份报告自包含，元数据和正文放在同一 Markdown 文件。用字符串保存日期，必填字段如下：

```yaml
---
title: "产品名：主要研究问题"
product: "产品名"
productSlug: "product-name"
website: "https://example.com"
date: "2026-11-17"
category: "AI 助手"
summary: "用 80–180 字概述核心结论、差异化与主要边界。"
tags: ["Agent", "协作"]
sources:
  - "https://example.com"
---
```

产品标识仅用小写英文、数字和连字符，目录名与 productSlug 一致；一个产品保留稳定标识。日期必须是真实日历日期并与文件名一致。正文不要再重复一级标题，网页从 title 生成标题。

必备二级章节：执行摘要、核心功能与产品定位、主要特性分析、商业模式与定价、市场分析（用户画像/竞品对比/市场口碑）、官网内容洞察、SWOT 分析、对 AI 产品经理的启发、结论与建议、待核实项。证据不足的章节如实说明，不填充虚构内容；没有待核实项时写“无”。

引用在正文就近使用普通 Markdown 链接，并在 sources 列出完整 URL；不要把会话内部 citation ID 存入文件。记录关键数据的适用地区、币种、税费与时间。网页自动从二级标题生成目录，Markdown 为唯一正文来源。禁止嵌入脚本、iframe 或原始 HTML。分类优先复用仓库现有值。
